## 人工验收步骤

在三平台分别记录 OS、编译器、SDL 版本、连接方式、手柄硬件/固件和每项结果：

1. 构建、运行 CTest，安装并编译 `tests/consumer`。
2. `dualforge_cli list` 确认识别，再运行 `monitor 30`：逐个按键、方向键、全行程摇杆/扳机、单指/双指触摸及旋转手柄。
3. 运行 `led 5`，确认 RGB、玩家灯及亮度；通过库 API 分别验证 FadeIn/FadeOut，再设 Nothing。
4. 运行 `rumble 3`，确认超时停止；逐项运行 `trigger <name> 3`，确认左右效果和退出停止。
5. 使用两个设备 ID 分别打开，交替发送灯光和扳机，确认互不影响；运行期间拔出，确认一次断开通知、无崩溃，重插后重新枚举新 ID。
6. 正常退出、Ctrl+C 退出和写入失败时确认震动/扳机停止。强制终止进程不保证有机会清理。

工作流位于仓库根目录 `.github/workflows/ci.yml`，推送后可自动触发；远程结果以 GitHub Actions 记录为准。

- 临时工具显式清零功率衰减后施加最大阻力，用户确认力度足够；随后原版 CLI 未发送清零字段时也确认阻力很强。由于清零状态可能保留，不能证明最初偏弱是功率衰减导致。项目默认输出逻辑未修改。
